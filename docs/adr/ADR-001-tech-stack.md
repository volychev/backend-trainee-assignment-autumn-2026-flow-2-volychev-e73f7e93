# ADR-001: Выбор технического стека

**Дата:** 2026-09-07  
**Статус:** Принято  
**Участники:** Team Lead, Backend Engineer

---

## Контекст

Необходимо разработать MVP сервиса доставки еды «Авито.Кухня» в сжатые сроки.  
Требования:
- Быстрый старт разработки без значительных накладных расходов на настройку
- Асинхронная обработка запросов (I/O-bound нагрузка: обращения к БД, HTTP-вебхуки)
- Автоматическая OpenAPI-документация (требование ТЗ)
- Единый стиль кода и инструменты качества
- Запуск через Docker Compose

Кандидаты на язык: **Python 3.13**, Golang.

---

## Решение

Выбран следующий стек:

| Компонент | Выбор | Альтернативы |
|---|---|---|
| Язык | **Python 3.13** | Golang |
| Фреймворк | **FastAPI** | Django REST Framework, Flask, aiohttp |
| СУБД | **PostgreSQL 16** | MySQL, SQLite |
| ORM | **SQLAlchemy 2.x (async)** | Tortoise ORM, raw asyncpg |
| Миграции | **Alembic** | Flyway, liquibase |
| Валидация | **Pydantic v2** | marshmallow, attrs |
| Конфигурация | **pydantic-settings** | python-decouple, dynaconf |
| Зависимости | **Poetry** | pip + requirements.txt, PDM |
| HTTP-клиент | **httpx** | aiohttp, requests |
| Тесты | **Pytest + pytest-asyncio** | unittest |
| Линтер | **Ruff** | flake8 + isort + black |
| Тайп-чекер | **mypy** | pyright |

### Обоснование выбора Python

- **Скорость разработки**: Python позволяет быстро прототипировать и итерировать на MVP
- **Богатая экосистема**: зрелые библиотеки для всех нужд (FastAPI, SQLAlchemy, Alembic)
- **asyncio**: полноценный async/await начиная с Python 3.7, в 3.13 — дальнейшие улучшения
- **Команда**: Python широко распространён среди backend-разработчиков

### Обоснование выбора FastAPI

- **OpenAPI из коробки**: автоматически генерирует `/docs`, `/redoc`, `/openapi.json`
- **Pydantic-интеграция**: валидация запросов/ответов без бойлерплейта
- **Async-first**: все эндпоинты `async def`, нет нужды в дополнительных настройках
- **Скорость**: один из самых быстрых Python-фреймворков (близок к Node.js по производительности)
- **Dependency Injection**: встроенная система зависимостей для сессий БД и т.д.

### Обоснование выбора PostgreSQL

- **ACID-транзакции**: критично для финансовых операций (заказы, цены)
- **Типы данных**: UUID, JSONB, TIMESTAMPTZ — всё нужное есть нативно
- **Зрелость**: проверено годами в production нагруженных систем
- **SQLAlchemy-совместимость**: первоклассная поддержка через asyncpg

### Обоснование выбора Poetry

- **pyproject.toml**: единый конфиг для зависимостей, линтеров, инструментов
- **Lock-файл**: `poetry.lock` гарантирует воспроизводимые сборки
- **Виртуальное окружение**: управляется автоматически

---

## Последствия

### Положительные

- Высокая скорость разработки MVP
- Автоматическая OpenAPI-документация без дополнительных усилий
- Типобезопасность через Pydantic + mypy
- Единый инструментарий (Ruff заменяет flake8 + isort + black)

### Отрицательные / Риски

- **Python vs Golang по производительности**: при росте нагрузки может потребоваться переход
  - *Митигация*: асинхронный стек (asyncio) + горизонтальное масштабирование
- **GIL**: Python GIL ограничивает CPU-bound параллелизм
  - *Митигация*: сервис I/O-bound (запросы к БД, HTTP), GIL не является узким местом
- **Молодость Python 3.13**: потенциальные несовместимости библиотек
  - *Митигация*: все выбранные библиотеки уже поддерживают 3.13
