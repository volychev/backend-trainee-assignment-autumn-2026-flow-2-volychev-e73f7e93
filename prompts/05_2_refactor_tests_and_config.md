CONTEXT:
Проект: MVP платформы доставки "Авито.Кухня".
Стек: Python 3.13, FastAPI, PostgreSQL, Pytest, Docker Compose.
Архитектура: Модульный монолит.
Текущее состояние: Инфраструктура, тесты и конфигурация реализованы, но в тестах присутствует захардкоженный URL базы данных, а структура самих тестов не стандартизирована.
Проблема: Хардкод `TEST_DATABASE_URL` в файлах тестов нарушает правила конфигурации через окружение. Тесты написаны сплошным кодом без четкого разделения на логические блоки, что снижает их читаемость.

ROLE:
Senior Backend Developer, QA Engineer

TASK:
Выполни рефакторинг тестового окружения и интеграционных тестов:
1. Вынеси конфигурацию подключения к базе данных для тестов в `app/core/config.py` (используя `pydantic-settings`, чтобы параметры подтягивались из переменных окружения или `.env`), избавившись от хардкода в файлах тестов.
2. Обнови `tests/conftest.py`, чтобы фикстуры брали настройки подключения к БД из централизованного конфига.
3. Отрефактори все файлы тестов в директории `tests/` в единый блочный стиль (паттерн AAA с отступами и комментариями для каждого шага):
   - **Подготовка (Arrange)**: создание тестовых данных в БД, подготовка заголовков (например, `X-User-ID`).
   - **Операция (Act)**: выполнение запроса к эндпоинту через `AsyncClient`.
   - **Валидация (Assert)**: проверка статус-кода, полей JSON-ответа и состояния базы данных.

INPUT / REFERENCES:
- @app/core/config.py
- @tests/conftest.py
- @tests/*

CONSTRAINTS & EXECUTION RULES:
- Строгий скоуп: реализуй исключительно то, что явно указано в блоке TASK.
- Каждый тест должен явно содержать блоки с комментариями: `# Подготовка`, `# Операция`, `# Валидация`.
- Конфигурация БД должна управляться через окружение/конфиг.

WHAT TO AVOID:
- Не хардкодь URL баз данных, хосты или пароли прямо в файлах тестов (`conftest.py` / `tests/`).
- Не меняй логику работы основной бизнес-логики и эндпоинтов.
- Не пиши заглушки (TODO/pass). Весь код тестов должен работать.
- Не взаимодействуй с Git, пока я не попрошу этого напрямую.
- Не добавляй массивных ASCII-форматированных комментариев. Максимум небольшие пояснения и разделения на блоки.

DEFINITION OF DONE:
Задача считается завершенной только тогда, когда:
1. Настройки БД вынесены в `config.py` и больше не захардкожены в коде тестов.
2. Все интеграционные тесты переписаны с использованием четких блоков (Подготовка, Операция, Валидация).
3. `conftest.py` успешно использует конфигурацию приложения.
4. Тесты успешно проходят при запуске через `pytest`.

OUTPUT FORMAT:
1. Обновленный код файла `app/core/config.py` (если затронут).
2. Обновленный код файла `tests/conftest.py`.
3. Обновленный код файлов в директории `tests/` с соблюдением блочной структуры.
