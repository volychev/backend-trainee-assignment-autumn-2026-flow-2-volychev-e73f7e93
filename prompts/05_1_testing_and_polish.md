CONTEXT:
Проект: MVP платформы доставки "Авито.Кухня".
Стек: Python 3.13, FastAPI, PostgreSQL, Pytest, Docker Compose.
Архитектура системы: SOA (Main API + Mock API).
Архитектура самого Main API: Модульный монолит.
Текущее состояние: Все сервисы реализованы, инфраструктура и вебхуки настроены.
Задача этапа: Реализовать базовый набор интеграционных тестов, зафиксировать подход в ADR и провести финальную проверку проекта.

ROLE:
Senior Backend Engineer, QA Engineer

TASK:
Реализовать набор тестов и оформить документацию тестирования:
1. Создать ADR для стратегии тестирования в папке `docs/adr/`.
2. Настроить окружение для тестирования (`pytest`, `pytest-asyncio`, `httpx`). Создать файл `conftest.py` с фикстурой асинхронного клиента (`AsyncClient` с `httpx` и `ASGITransport`) для Main API.
3. Написать интеграционные тесты в директории `tests/`:
   - `test_restaurants.py` — проверка эндпоинта получения списка ресторанов (`GET /restaurants`).
   - `test_menu.py` — проверка получения меню заведения (`GET /restaurants/{id}/menu`).
   - `test_orders.py` — проверка полного цикла заказа (`POST /orders`, проверка генерации `order_id`, статуса `PENDING` и корректного расчёта суммы).
   - `test_webhooks.py` — проверка эндпоинта обновления статуса заказа от ресторана (`PATCH /orders/{id}/status`).
4. Убедиться, что код проходит проверки статического анализатора `ruff` и тайп-чекера `mypy` без критических ошибок.

INPUT / REFERENCES:
- @app/main.py
- @README.md
- docs/adr/*

CONSTRAINTS & EXECUTION RULES:
- Строгий скоуп: реализуй исключительно то, что явно указано в блоке TASK.
- Используй `httpx.AsyncClient` с `ASGITransport` для асинхронного тестирования FastAPI эндпоинтов.
- Тесты должны быть изолированными и использовать асинхронную тестовую сессию БД.

WHAT TO AVOID:
- Не меняй основную бизнес-логику приложения.
- Не пиши заглушки (TODO/pass). Все тесты должны быть рабочими.
- Не взаимодействуй с Git, пока я не попрошу этого напрямую.
- Не добавляй массивных ASCII-форматированных комментариев в код. Максимум небольшие пояснения.

DEFINITION OF DONE:
Задача считается завершенной только тогда, когда:
1. Создан ADR-файл с описанием стратегии тестирования в папке `docs/adr/`.
2. Создана директория `tests/` с набором рабочих тестов и настроенным `conftest.py`.
3. Код успешно проходит проверки статического анализа (`ruff` / `mypy`).
4. Предоставлена инструкция по запуску тестов внутри Docker-контейнера (`docker compose exec main-api pytest`).

OUTPUT FORMAT:
1. Полный код файлов в директории `tests/`, `conftest.py` и нового ADR файла с указанием путей.
2. Команда для запуска тестов и линтеров через терминал.
