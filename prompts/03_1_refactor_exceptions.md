CONTEXT:
Проект: MVP платформы доставки "Авито.Кухня".
Стек: Python 3.13, FastAPI, PostgreSQL.
Архитектура: Модульный монолит.
Текущее состояние: Основной API (Main API) реализован.
Проблема: В текущей реализации бизнес-логика (`service.py`) напрямую зависит от FastAPI, выбрасывая `HTTPException`. Это нарушает принцип разделения слоев (Separation of Concerns). Мы хотим изолировать доменные ошибки от веб-фреймворка.

ROLE:
Senior Backend Developer, System Architect

TASK:
Выполни рефакторинг обработки ошибок:
1. Создай базовый класс ошибок `app/core/exceptions.py`, унаследованный от стандартного `Exception`. Например, `class BaseAppException(Exception): ...`
2. Создай файлы `exceptions.py` в каждом модуле (`app/restaurants/`, `app/menu_items/`, `app/orders/`) и определи в них специфичные доменные ошибки, унаследованные от базовой (например: `RestaurantNotFoundError`, `MenuItemUnavailableError`, `OrderNotFoundError`).
3. Отрефактори все `service.py`. Замени вызовы `raise HTTPException(...)` на выброс новых кастомных доменных ошибок. Теперь `service.py` не должен импортировать ничего из `fastapi`.
4. Обнови `app/main.py`. Напиши и зарегистрируй через `@app.exception_handler` глобальные обработчики для новых доменных ошибок. Эти обработчики должны перехватывать доменную ошибку и возвращать `JSONResponse` с правильным HTTP-статусом (404 для Not Found, 400 для бизнес-правил) и понятным сообщением.

INPUT / REFERENCES:
- @app/main.py
- @app/*/service.py

CONSTRAINTS & EXECUTION RULES:
- Строгий скоуп: реализуй исключительно то, что явно указано в блоке TASK.
- Сервисы (`service.py`) должны оставаться чистыми.
- Сообщения об ошибках в ответах JSON должны сохранить структуру, ожидаемую клиентом (например, `{"detail": "Order not found"}`).

WHAT TO AVOID:
- Не меняй логику работы эндпоинтов и SQLAlchemy-запросов, только обработку исключений.
- Не пиши заглушки (TODO/pass). Весь код должен быть рабочим.
- Не взаимодействуй с Git, пока я не попрошу этого напрямую.
- Не добавляй массивных ASCII-форматированных комментариев в код. Максимум небольшие пояснения и разделения на блоки.

DEFINITION OF DONE:
Задача считается завершенной только тогда, когда:
1. Созданы файлы `exceptions.py` в `core` и бизнес-модулях.
2. Из `service.py` полностью удалены импорты `HTTPException`.
3. В `main.py` добавлены обработчики (exception_handlers), корректно мапящие кастомные ошибки в `JSONResponse`.
4. Приложение успешно запускается и корректно отдает 404/400 ошибки при невалидных запросах.

OUTPUT FORMAT:
1. Полный код новых файлов `exceptions.py` с указанием пути.
2. Обновленный код файлов `service.py` и `main.py`.
