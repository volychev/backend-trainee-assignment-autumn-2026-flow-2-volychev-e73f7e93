CONTEXT:
Проект: MVP платформы доставки "Авито.Кухня".
Стек: Python 3.13, FastAPI, PostgreSQL, Pytest, Docker Compose, Ruff, Mypy.
Архитектура системы: SOA (Main API + Mock API).
Архитектура самого Main API: Модульный монолит.
Текущее состояние: Все сервисы реализованы, написаны интеграционные тесты, настроен линтинг и статическая типизация.
Задача этапа: Настроить автоматический CI/CD пайплайн на базе GitHub Actions для проверки качества кода и запуска тестов при каждом пуше или пулл-реквесте.

ROLE:
DevOps Engineer, Senior Backend Engineer

TASK:
Настроить GitHub Actions пайплайн для автоматической проверки проекта:
1. Создать файл конфигурации GitHub Actions по пути `.github/workflows/ci.yml`.
2. Настроить триггеры запуска пайплайна: при push и pull_request в ветки `main` или `master`.
3. Описать шаги пайплайна (jobs):
   - **Линтинг и типизация**: установка Python 3.13, Poetry, запуск линтера `ruff` и тайп-чекера `mypy`.
   - **Интеграционные тесты**: поднятие сервиса PostgreSQL в виде ephemeral service (или через встроенный контейнер GitHub Actions), инициализация окружения, применение миграций Alembic и запуск тестов `pytest`.
   - **Сборка образов (Build)**: проверка сборки Docker-образов (`Dockerfile` и `Dockerfile.mock`), чтобы убедиться, что контейнеры собираются без ошибок.
4. Создать ADR для выбора и описания CI/CD стратегии в папке `docs/adr/`.

INPUT / REFERENCES:
- @pyproject.toml
- @docker-compose.yml
- @README.md

CONSTRAINTS & EXECUTION RULES:
- Строгий скоуп: реализуй исключительно то, что явно указано в блоке TASK.
- Используй современные версии GitHub Actions (например, `actions/checkout@v4`, `actions/setup-python@v5`).
- Подключение к базе данных в тестах в CI должно использовать тестовую БД (например, через переменные окружения).

WHAT TO AVOID:
- Не меняй бизнес-логику приложения и исходный код тестов.
- Не настраивай деплой на продакшн (скоуп ограничен только CI-проверками для MVP).
- Не взаимодействуй с Git, пока я не попрошу этого напрямую.
- Не добавляй массивных ASCII-форматированных комментариев. Максимум небольшие пояснения.

DEFINITION OF DONE:
Задача считается завершенной только тогда, когда:
1. Создан файл конфигурации `.github/workflows/ci.yml` с валидным синтаксисом YAML.
2. Создан ADR-файл с описанием CI/CD пайплайна в папке `docs/adr/`.
3. Пайплайн включает шаги для линтинга (`ruff`, `mypy`), тестирования (`pytest` с поднятым PostgreSQL) и проверки сборки Docker.

OUTPUT FORMAT:
1. Полный код файла `.github/workflows/ci.yml` и нового ADR файла с указанием путей.
2. Краткое описание этапов пайплайна.
